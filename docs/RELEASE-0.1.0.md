# Guncat Work 电脑版 0.1.0 —— 首次公开

> **历史文档**：`0.1.0` 属于测试版本，正式版及当前全部能力见
> [更新记录](../CHANGELOG.md) 的 `7.0.0` 一节；本文保留当时的发布说明，数字与结论
> 均只代表 `0.1.0` 当时的状态。

**鸿蒙版 [Guncat Work](https://github.com/zhubowen-bot/Guncat-Work-for-hmos) 的桌面移植。**
用 Electron + React + TypeScript 复刻的 Agent Harness 客户端：一个窗口里同时装着
「一句话直出可操作界面」和「多轮工具循环自主干活」两种当下最当红的 Agent 形态。

> 内核不是重写的 —— Agent Loop、三协议流式对话、45 个内置工具、37 项技能、
> Office 生成器、`guncat-ui lang` 渲染器，约 3.5 万行 TypeScript 从 ArkTS **逐字移植**而来，
> 平台依赖全部收敛在 `@kit.*` 别名后面。

## 三个形态

| 形态 | 对标 | 一句话 |
| --- | --- | --- |
| ✦ **交互模式** | GPT 的 Intelligent UI | 回答不是纯文本，而是一份**界面程序** —— 可拖、可点、改参数**即时重算** |
| 🛠 **工作模式** | DeepSeek Harness（Codex 式 Agent Loop） | 多轮工具循环 + 每会话独立沙箱工作区，长程任务自主执行 |
| 聊天模式 | — | 纯对话 |

工作模式与交互模式**共用同一套 Agent Loop 与沙箱工作区**，差别在下发的工具面：
工作模式是 45 个工具全量 + 多轮循环；交互模式只下发 27 个（读素材 / 算真实数字 /
核实外部事实 / 出文件），长程工具根本不出现在它的请求里 —— 所以它是「快车道、一轮直出」。

## 为什么值得一试

- **桌面端直出 Office，不消耗多模态配额。** PPT / Word / Excel / SVG 由本地生成器产出，
  基于 JSON 中间层，文档可**无损读回、算子式编辑**；PDF 与 Office 全部本地解析。
- **交互模式有 76 个组件。** 8 种图表（柱状 / 折线 / 面积 / 横向条 / 饼环 / 径向 / 雷达 / 堆叠条）、
  表格、指标卡、图片墙、选项卡 / 折叠面板 / 步骤条，加整套表单控件；
  `$绑定`重算与动作回传都是原生实现，不是截图。
- **45 个内置工具 + 37 项技能。** 文件增删改查与模式匹配搜索、任务清单、PDF 解析、
  Office 读写、数据管道清洗与格式互转，以及基于 `node:vm` 的 `run_js` 代码沙箱 ——
  不联网、不读写文件系统，**死循环能被引擎硬中断**。
- **三协议接入。** OpenAI Completions / OpenAI Responses / Anthropic Messages，均支持图片直传，
  深度思考与联网搜索按各协议显式控制；内置本地联网搜索，工作模式与聊天模式都能用。
- **原生 Markdown。** 代码高亮、LaTeX 行内与块级公式、Mermaid 图表（导图规范按**桌面宽屏**口径，
  可横向滚动），深浅色主题自动适配。
- **语音、附件、导出。** 朗读（可切系统音色与倍速）+ 语音输入（录音 + 服务商转写）；
  文件拖进窗口即导入工作区；回答可导出为 Word（含 LaTeX → OMML 原生公式）。

## 这一版里有什么

首次公开，从零到「双击即可用」的全部工作都在这一版。完整清单见
**[CHANGELOG](CHANGELOG.md)**，这里只挑三件最能说明问题的事：

**一、把「实现了但没人用」的那一批补上了。**
比起功能缺失，这类问题更隐蔽 —— 代码看起来是齐的，用户却会遇到「模型说会提醒你，
到点什么都不发生」。定时提醒、聊天模式附件、产物汇总卡、插件热加载、上下文预算管理、
`ask_user_question`、会话标题…… 一共几十处「内核有能力、零调用点」，这一版逐个接上了调用者。
同一轮里还逐文件对照原版做了一次**全量对标审计**，把「原版有、桌面端口径不同」的
语义与规格差异一条条校准。

**二、修掉三处会真的伤到用户的缺陷。**

| 缺陷 | 后果 |
| --- | --- |
| 把 `readTimeout` 当成整段超时 | 工作模式流式超 5 分钟、聊天超 3 分钟**必然以网络错误中断**，哪怕数据一直在流。已改成**读空闲**计时 |
| PDF / SVG 后端缺席 | 被包装成「文件损坏」，于是**任何** PDF 都得到同一句「文档结构损坏」。现在接上了 PDF.js 与 `@napi-rs/canvas` |
| 提示词把桌面版描述成手机应用 | 模型自称「在 HarmonyOS 平台原生构建」、说「无法访问手机其他目录」。22 处平台语义改为桌面措辞 |

**三、为「开发机上 GUI 不一定起得来」这件事专门做了工程。**
四套**无头**冒烟把风险最高的移植内核拉到纯 Node 下按真实调用链跑一遍 ——
元素树 → React 组件树、每个 IPC 通道真实 invoke、真实入口 `src/main/index.ts` 全链路，
Windows 上合计约 **1010 项断言**，一条 `npm run verify` 跑完。
打包产物还附了 `diagnose.cmd`，起不来时一次跑 6 档并逐档给出结论。

## 已知限制

- **只有 Windows 版本。** 这一版的目标平台就是 Windows。
- **未签名**，首次运行会被 SmartScreen 拦一次（见上）。
- **安装与卸载各需要一次管理员授权**（装 `Program Files` 和写 `HKLM` 绕不开）。
- **部分 Windows 开发机上，带沙箱启动的 Electron 建不出 GPU 子进程**，Chromium 会直接自杀
  （退出码 `-2147483645`）。14 组对照实验证明只有 `--no-sandbox` 能改变结果，
  所以**打包产物会在启动第一刻自我重启一次把该参数带上** —— 你可能会看到进程「闪一下又起来」，
  这是预期行为，不是崩溃。`npm run dev` 刻意保留沙箱，用来留一条能复现根因的路径。
  根因与诊断阶梯见 **[启动排障](docs/STARTUP-TROUBLESHOOTING.md)**。

## 开始使用

1. 装好后启动，点左下角「设置」；
2. 填入接入方式（OpenAI Completions / OpenAI Responses / Anthropic）、Base URL、API Key 与模型，保存；
3. 回到主界面就能开始对话。想让它干活就切到「工作模式」。

对话历史、沙箱工作区与配置存在 `%APPDATA%\Guncat Work`，不写程序目录 ——
卸载时可以选择是否连它们一起删。
